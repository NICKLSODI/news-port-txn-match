# News–Customer Matching — Concept (ฉบับย่อสำหรับ Dev)

> อ่านไฟล์นี้ไฟล์เดียวก็เริ่มงานได้ ส่วน STEP1–STEP8 ใช้เป็น**คู่มืออ้างอิงตอนลงรายละเอียด** (ในนี้จะชี้ว่าเรื่องไหนอยู่ไฟล์ไหน)

---

## 1. ระบบนี้ทำอะไร

**ข่าวใหม่ลง Cafe Invest 1 ชิ้น → ระบบบอก RM ว่าควรโทรหาลูกค้าคนไหน เรียงตามลำดับความสำคัญ**

เป็น **news-centric** (ข่าวเข้า → รายชื่อลูกค้าออก) ไม่ใช่ customer-centric
ผลลัพธ์ส่งให้ **RM** ไม่ได้ส่งหาลูกค้าโดยตรง
**ไม่มีข่าว = ไม่ส่ง** ไม่ต้องฝืนหา

---

## 2. Data flow

```
[1] ดึงข่าว        Cafe Invest JSON API (มี public API — ไม่ต้อง scrape)
        ↓
[2] แท็กข่าว       ได้ entity (ticker), sector, importance, urgency, macro_topic
        ↓
[3] แปลงรหัส       ticker ฝั่งข่าว ↔ ฝั่งลูกค้า ให้เป็นรูปแบบเดียวกัน
        ↓
[4] จับคู่          L1–L6 (แม่น → กว้าง)
        ↓
[5] ให้คะแนน+เรียง  score = น้ำหนักระดับ × มูลค่าถือ × importance × urgency × recency
        ↓
[6] กรอง+ส่ง       ตัดที่คะแนนขั้นต่ำ → กรอง persona → ส่งให้ RM เจ้าของลูกค้า
```

---

## 3. Input ที่ต้องมี

| แหล่ง | ได้อะไร | อ้างอิง |
|---|---|---|
| **Cafe Invest API** | บทความ + ticker ที่ติดมากับข่าว | STEP2 (ชีต API Spec) |
| **Portfolio** (รายสัปดาห์) | ลูกค้าถืออะไร มูลค่าเท่าไหร่ | STEP1 |
| **TXN** (rolling 6 เดือน) | ลูกค้าเทรดอะไร เมื่อไหร่ | STEP1 |

**API endpoint:**
```
GET https://www.innovestx.co.th/cafeinvest/api/cafe/v1/content/search
    ?lang=THA&user_type=visitor&content_type=article
    &category_slug=…&sub_category_slug=…&limit=100&page=1
```
ตอบกลับ `result.data[]` + `result.total` — ไม่ต้อง auth

⚠️ **ข้อมูลลูกค้าถูก mask มาแล้ว** — `customer_key` / `account_key` / `rm_id` เป็นรหัส ไม่มีชื่อหรือเลขบัตร ระบบทำงานบนรหัสล้วน ตอน RM จะโทรค่อยแปลงกลับที่ฝั่ง CRM

## 4. หัวใจ: ระดับการจับคู่ L1–L6

| ระดับ | เงื่อนไข | น้ำหนัก |
|---|---|---|
| **L1 ถือตรงตัว** | ข่าวพูดถึงตัวที่ลูกค้าถืออยู่ | 100 |
| **L2 watchlist** | เคยเทรดใน 90 วัน แต่ตอนนี้ไม่ถือ | 60 |
| **L3 sector** | ถือหุ้น sector เดียวกับข่าว (หุ้นไทยเท่านั้น) | 40 |
| **L4 ความสัมพันธ์** | ถือหุ้นที่สัมพันธ์กับตัวในข่าว (ใช้กับหุ้นนอกที่ไม่มี sector) | 30 |
| **L5 asset class** | ข่าวประเภทเดียวกับที่ลูกค้าถือ | 20 |
| **L6 macro** | ทุกคน แต่ถ่วงตามความไวของพอร์ต | 10 |

ลูกค้าเข้าหลายระดับ → **ใช้ระดับสูงสุดเป็นฐาน + โบนัสถ้าแตะหลายจุด**

**ทุกการจับคู่ต้องบันทึกหลักฐาน** ว่าเข้าระดับไหน เพราะ entity ตัวไหน → RM ต้องเห็นเหตุผล

📖 รายละเอียด: **STEP6**

---

## 5. สูตรจัดอันดับ

```
score = base_weight(L1..L6) × f(มูลค่าถือ) × f(importance) × f(urgency) × f(recency)
```

- **มูลค่าถือ** — ถือ 20 ลบ. มาก่อนถือ 50,000
- **importance** 1–5 — งบการเงินสำคัญกว่าข่าวทั่วไป (มาจาก content_type)
- **urgency** — `now` / `this_week` / `low`
- **recency** — เพิ่งเทรดตัวนั้น = กำลังสนใจ ได้แต้มเพิ่ม

🚫 **ไม่มี sentiment** — ตัดทิ้งตั้งแต่ออกแบบ เพราะทดสอบแล้วเชื่อถือไม่ได้ (งบดี/ร้ายขึ้นกับว่าลูกค้าถือหรือ short) ใช้แต่ข้อเท็จจริงที่ตรวจสอบได้

## 6. สองโหมดการทำงาน

| โหมด | ใช้กับ | จับคู่ถึงระดับ | ส่งเมื่อไหร่ |
|---|---|---|---|
| **Real-time Trigger** | ข่าวรายตัว (Earnings, Company Update, Offshore Update) | L1–L2 เท่านั้น | ทันทีที่บทความออก |
| **Daily Digest** | ข่าวรวม (Morning/Evening Brief, TFEX Daily) | ถึง L4 | รอบเช้า + เย็น |

⚠️ Morning/Evening Brief ต้อง**ซอยเป็นข้อย่อยก่อน** (5–7 ข้อ ไม่คงที่) แล้วค่อยจับคู่รายข้อ

## 8. หลักการที่ห้ามละเมิด (สำคัญสุด)

1. **ความถูกต้องมาก่อนความครอบคลุม** — แท็กได้น้อยแต่ถูก ดีกว่าแท็กเยอะแต่ผิด
2. **ไม่มั่นใจ = ไม่จับคู่** — ส่งเข้า unmapped + ออกรายงาน ห้ามเดา
3. **ทุกการจับคู่อ้างหลักฐานได้** — เก็บ evidence ทุกครั้ง
4. **ห้ามสร้างข้อมูลที่ไม่มีในต้นทาง** — บทความไม่ได้บอก ห้ามเติมเอง
5. **ใช้กฎ ไม่ใช่ hardcode list** — ไฟล์ข้อมูลเป็นแค่ sample ของจริงจะต่างไป

**3 ระดับความมั่นใจของ entity:**
`confirmed` (จาก API ใช้ได้เลย) · `inferred` (**ต้องมีคนตรวจก่อนใช้จับคู่จริง**) · `unknown` (→ unmapped)

---

## 9. ข้อจำกัดที่รู้อยู่แล้ว (อย่าเสียเวลาแก้)

- **หุ้นนอกไม่มี sector** → ใช้ L4 ตารางความสัมพันธ์แทน L3
- **กองทุน 54% แกะ underlying ไม่ได้** (`product_name` เป็น `'null'` ทุกแถว ไม่มี fund master) → coverage ที่ทำได้จริง 46.5%
- **ETF + ตราสารหนี้ต่างประเทศ ไม่มีข่าวรองรับเลย**
- **หุ้นนอกไม่มี Target Price** (มีแต่หุ้นไทย จาก Coverage List 97 ตัว)
- **TFEX ใน Portfolio เป็นยอดเงินในบัญชี ไม่ใช่สถานะ** → ต้องคำนวณจาก txn แทน
- **ภาษาไทยไม่มีการเว้นวรรค** → ห้าม match keyword สั้น ("ยา" ไป match "อย่าง"/"ยาว" ทำให้ 35% ของข่าวถูกแท็กผิด) ใช้คำยาวเฉพาะเจาะจงเท่านั้น

---

## 10. ลำดับที่แนะนำให้สร้าง

1. ดึง API + เก็บบทความ (STEP2)
2. แท็กข่าว 23 field (STEP3)
3. ตารางแปลงรหัส ticker (STEP4) ← **งานหนักสุด แต่เป็นฐานของทุกอย่าง**
4. คำนวณ customer features + persona (STEP5)
5. เครื่องจับคู่ + จัดอันดับ (STEP6)
6. หน้าจอ RM (STEP7)
7. รายงาน unmapped/exception (STEP8)
